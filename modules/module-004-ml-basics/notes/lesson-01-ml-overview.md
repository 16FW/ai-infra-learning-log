# Lesson 01. ML Overview: 모델이란 무엇이고, 인프라는 무엇을 책임지는가

## 핵심 개념
- 머신러닝은 규칙을 코드로 쓰는 대신 데이터로부터 규칙(함수)을 학습시키는 방식이다.
- 모델 = 계산 구조(클래스) + 학습된 파라미터(계수, 절편 등)의 결합이다.
- 학습(training)은 데이터로 파라미터를 갱신하는 배치성 작업이고, 추론(inference)은 학습된 파라미터로 새 입력을 계산하는 상시 서빙 작업이다.
- ML 워크플로: 데이터 수집 → 준비 → 학습 → 평가 → 배포 → 추론 → 모니터링/재학습.

## 동작 원리
- `joblib.dump(model)`은 학습된 상태(coef_, intercept_)와 클래스 참조(모듈 경로 + 이름)를 파일로 저장한다. 클래스의 구현 코드는 저장되지 않는다.
- `joblib.load()`는 클래스 참조를 따라 `__import__`로 라이브러리를 찾아 객체를 복원한다. 그래서 `infer.py`에 import가 없어도 동작하지만, sklearn이 없으면 `ModuleNotFoundError`가 난다.
- pickle 계열 파일은 로드 시 코드가 실행될 수 있어 출처 불명 파일은 위험하다.

## 실습에서 한 것
- Iris 데이터로 LogisticRegression을 학습해 `model.joblib`로 저장(`train.py`)하고, 별도 프로세스에서 불러와 예측(`infer.py`)했다. 결과는 `[0]`(setosa).
- `coef_` (3,4) + `intercept_` (3,) = 학습 파라미터 15개, 파일 크기는 975 bytes였다.
- sklearn이 없는 새 venv에서 `infer.py`를 실행해 `No module named 'sklearn'`을 재현했다.
- 7B 모델을 fp16으로 올리면 가중치만 14GB(= 약 13.04GiB)임을 계산하고 python으로 검증했다.

## Infrastructure 연결
- 모델 파일은 MLflow Model Registry에 등록되고 Docker 이미지에 들어가는 아티팩트다.
- "추론 환경에도 같은 라이브러리·버전이 필요" → Dockerfile에서 의존성 버전을 고정해야 하는 이유.
- 가중치 + KV 캐시 + 중간 계산값 + 여유 메모리 → Kubernetes GPU/메모리 resource request의 근거.

## 면접 포인트
- 모델 파일에는 학습 결과와 클래스 참조만 있고 구현 코드는 없다. 그래서 실행 환경 재현(버전 고정, Docker)이 필요하다.
- GPU 서빙 용량은 가중치 크기만이 아니라 KV 캐시와 여유 메모리까지 더해 산정해야 한다.

## 내 말로 3줄 요약
1. ML 모델은 계산 구조(클래스)와 데이터로 학습된 파라미터의 결합이며, 학습은 파라미터를 만드는 일, 추론은 그 파라미터로 새 입력을 계산하는 일이다.
2. 모델 파일에는 학습 결과와 클래스 참조만 있고 구현 코드는 없어서, 추론 환경에도 같은 라이브러리와 호환 버전이 설치되어 있어야 복원된다.
3. 서빙 용량은 가중치(7B fp16 ≈ 14GB)만이 아니라 KV 캐시·중간 계산값·여유 메모리까지 더해 산정해야 하고, 그래서 환경 버전 고정(Docker)과 메모리 산정이 인프라의 핵심이다.
