# Lesson 03 — pytest로 테스트 작성

## 핵심 개념
- 테스트는 손으로 실행하고 눈으로 확인하던 작업을 코드로 자동화한 것이다.
- 함수를 "계약"으로 보고, 테스트는 그 계약을 코드로 명시한다.
- 좋은 테스트는 결정적(deterministic)이어야 한다. 어디서, 몇 번 실행해도 같은 결과가 나와야 한다.
- dict 반환과 명확한 예외 설계는 우연이 아니라 테스트하기 쉬운 코드를 만드는 설계다.

## 동작 원리
- pytest는 `test_*.py` 파일의 `test_*` 함수를 자동으로 찾아 실행한다.
- 평범한 `assert`만 써도 되는 이유: pytest가 assertion rewriting으로 실패 시 실제 값들을 보여준다.
- `pytest.raises(X)`는 블록 안에서 X 예외가 발생해야 통과한다.
- `tempfile.TemporaryDirectory()`를 with와 쓰면 블록이 끝날 때 폴더가 삭제된다. 중간에 에러가 나도 삭제가 보장된다.
- `isinstance` 체크를 먼저 하면 `None >= 1` 같은 TypeError로 테스트가 깨지는 대신, 의도한 실패로 처리된다.

## 실습에서 한 것
- `get_os_info`, `get_cpu_count`, `get_disk_usage`의 성공/실패 케이스 테스트 4개를 작성했다.
- `/` 하드코딩 대신 임시 디렉토리를 써서 다른 환경(컨테이너, CI 서버)에서도 통과하게 했다.
- assert를 with 블록 밖에 뒀다가, 임시 자원이 살아있는 범위 안에서 검증하도록 안으로 옮겼다.

## Infrastructure 연결
- CI는 push할 때마다 이 테스트를 자동으로 실행하는 것이다. (→ Module 010, Project 05의 GitHub Actions)
- 테스트가 환경에 의존하지 않아야 Docker 컨테이너와 CI 서버에서 똑같이 돌아간다. (→ Module 005)

## 면접 포인트
- 테스트에서 결정성이 왜 중요한가.
- tempfile과 with를 함께 쓰는 이유: 리소스 누수 방지.

## 내 말로 3줄 요약
1. 테스트는 함수를 자동 검증하는 코드이며, 실행 환경이나 횟수에 상관없이 언제나 동일한 결과를 내는 결정성이 핵심이다.
2. `/` 같은 외부 경로에 의존하지 않고 tempfile처럼 필요한 자원을 테스트가 스스로 만들어야 CI 서버나 Docker 컨테이너에서도 신뢰성 있게 실행된다.
3. dict 반환과 명확한 예외 설계 덕분에 테스트 작성이 쉬웠다. 좋은 설계가 테스트하기 쉬운 코드를 만든다.
